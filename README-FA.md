# Project Onboarding
از این Skill زمانی استفاده کن که کاربر می‌خواهد یک پروژه موجود بررسی، اجرا یا بیلد شود.

## هدف
پروژه را بدون حدس زدن بررسی کن، وابستگی‌ها و دستورهای لازم را پیدا کن، سپس به ترتیب اجرا و بیلد کن.

## مراحل
1. ابتدا ساختار پروژه را بررسی کن:
   - `ls -la`
   - `find . -maxdepth 2 -type f | head -100`
   - بررسی فایل‌های `README*`, `package.json`, `requirements.txt`, `pyproject.toml`, `Pipfile`, `Cargo.toml`, `go.mod`, `pom.xml`, `build.gradle`, `pubspec.yaml`, `Makefile`, `docker-compose.yml`, `Dockerfile`

2. نوع پروژه و ابزارهای لازم را تشخیص بده:
   - Node.js / npm / pnpm / yarn / bun
   - Python / pip / uv / poetry
   - Flutter / Dart
   - React Native
   - Android / Gradle
   - Go / Rust / Java
   - Docker / Docker Compose

3. وابستگی‌ها را بررسی کن:
   - اگر `node_modules` وجود ندارد، دستور نصب مناسب را اجرا کن.
   - اگر `venv` یا `__pycache__` وجود ندارد، محیط پایتون را آماده کن.
   - اگر فایل قفل وجود دارد، از آن استفاده کن؛ مثلاً `package-lock.json`, `pnpm-lock.yaml`, `yarn.lock`, `poetry.lock`, `uv.lock`.

4. فایل‌های محیطی را بررسی کن:
   - دنبال `.env.example`, `.env.sample`, `config.example.*`, `README` بگرد.
   - هر متغیر محیطی لازم را فهرست کن.
   - هرگز کلید یا رمز واقعی نساز؛ فقط از کاربر بخواه آن‌ها را وارد کند.
   - اگر لازم است، از نمونهٔ موجود یک `.env` محلی بساز و مقادیر را خالی بگذار.

5. دستورهای اجرا و بیلد را پیدا کن:
   - در `package.json` بخش `scripts` را بررسی کن.
   - در `README` دنبال بخش Install، Run، Development و Build بگرد.
   - در `Makefile`، `docker-compose.yml` و فایل‌های پیکربندی بررسی کن.
   - اگر چند روش وجود دارد، روش رسمی و کم‌ریسک‌تر را انتخاب کن و دلیلش را بگو.

6. قبل از اجرای هر دستور مهم:
   - دستور را با دلیل کوتاه توضیح بده.
   - دستورهای نصب، حذف، اجرای سرور، بیلد و تغییر فایل را فقط پس از تأیید کاربر اجرا کن.
   - هرگز `node_modules`، `.git`، `dist`، `build`، `venv` یا فایل‌های محیطی را حذف نکن، مگر کاربر صریحاً اجازه دهد.

7. اجرای برنامه:
   - ابتدا دستور اجرای محلی را اجرا کن.
   - آدرس localhost یا پورت را از خروجی پیدا کن.
   - اگر سرور اجرا شد، وضعیت آن را گزارش بده.
   - اگر خطا بود، لاگ کامل را بررسی کن، علت احتمالی را پیدا کن و کمترین تغییر لازم را پیشنهاد بده.

8. بیلد پروژه:
   - ابتدا پروژه را اجرا و تست کن.
   - سپس دستور بیلد رسمی پروژه را اجرا کن.
   - مسیر خروجی بیلد را پیدا و گزارش کن.
   - اگر بیلد شکست خورد، خطاها را دسته‌بندی کن: وابستگی، نسخه، متغیر محیطی، پیکربندی یا کد.

## قواعد مهم
- قبل از تغییر کد، همیشه علت مشکل را توضیح بده.
- حدس نزن؛ اگر اطلاعات کافی نیست، از کاربر سؤال بپرس.
- تغییرات را کوچک و قابل بازگشت انجام بده.
- در پایان یک گزارش کوتاه بده:
  - نوع پروژه
  - وابستگی‌های نصب‌شده
  - متغیرهای محیطی لازم
  - دستور اجرا
  - دستور بیلد
  - مسیر خروجی بیلد
  - خطاهای باقی‌مانده و راه‌حل پیشنهادی
